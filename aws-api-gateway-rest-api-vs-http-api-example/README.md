# One orders API, two API Gateway types

The same small orders API (`GET /orders/{orderId}`, `POST /orders`) is defined twice with AWS SAM:

- `template-rest.yaml`: an API Gateway **REST API** (API Gateway v1) with an API key on every method, a usage plan that throttles each key, and a JSON Schema request validator on `POST /orders`.
- `template-http.yaml`: an API Gateway **HTTP API** (API Gateway v2) with a JWT authorizer, one stage-wide throttle, and Lambda payload format 2.0.

One Lambda handler (`app/handler.py`) serves both. It reads both event formats (1.0 from the REST API, 2.0 from the HTTP API) and always returns the full proxy response, which both API types accept.

**Nothing here is deployed.** The project was built and checked without an AWS account: both templates are linted and validated, expanded offline into their CloudFormation resources, the handler is unit-tested with events generated by `sam local generate-event`, and a small local stand-in (`local_gateway.py`) calls the handler over HTTP. The stand-in is not API Gateway: it only reproduces the event formats and the documented response rules, and does no authorization, throttling or validation.

## Versions

- Python 3.13 (the Lambda runtime in the templates is `python3.13`)
- aws-sam-cli 1.171.0, aws-sam-translator 1.115.0, cfn-lint 1.58.0, pytest 9.1.1 (pinned in requirements.txt)
- curl for `demo.sh`
- Prices in `pricing.py`: US East (N. Virginia), from https://aws.amazon.com/api-gateway/pricing/ on 2026-10-31

## Files

| File | What it does |
|---|---|
| template-rest.yaml | REST API: Regional endpoint, API key required, usage plan (10 requests/s, burst 20, 10,000 requests/month per key), request validation |
| template-http.yaml | HTTP API: JWT authorizer (issuer and audience are parameters), stage throttle 50 requests/s, burst 100, payload format 2.0 |
| app/handler.py | Orders handler for both event formats; orders are kept in memory |
| events/ | Sample events from `sam local generate-event apigateway aws-proxy` and `... http-api-proxy` |
| tests/test_handler.py | Unit tests of the handler with both formats, plus checks of `pricing.py` against the AWS pricing examples |
| show_resources.py | Expands each SAM template offline and lists the CloudFormation resources it creates |
| pricing.py | Monthly request charges for both API types |
| local_gateway.py | Local stand-in that turns HTTP requests into 1.0 or 2.0 events and calls the handler |
| demo.sh | Runs everything above |
| OUTPUTS.txt | Output of one run of `PORT=20720 ./demo.sh` |

## How to run

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
./demo.sh                        # uses port 8000; set PORT to change it
```

## How to deploy (not run for the article)

With an AWS account, credentials and a JWT issuer (for example an Amazon Cognito user pool), each template deploys on its own:

```bash
sam deploy --guided -t template-rest.yaml --stack-name orders-rest
sam deploy --guided -t template-http.yaml --stack-name orders-http \
  --parameter-overrides JwtIssuer=https://cognito-idp.<region>.amazonaws.com/<pool-id> JwtAudience=<app-client-id>
```

The REST API needs the generated API key in an `x-api-key` header (`aws apigateway get-api-key --api-key <ApiKeyId output> --include-value`). The HTTP API needs `Authorization: Bearer <access token>` from your issuer. Delete the stacks with `sam delete` when you are done.
